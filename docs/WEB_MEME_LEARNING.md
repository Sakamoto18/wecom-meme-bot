# 指定梗联网学习

普通群成员可以在同一条消息中 @机器人发送 `/learn-meme 胆子真是肥嘟嘟的`，也支持 `联网学习 胆子真是肥嘟嘟的 这个梗`、`帮我去网上学习一下“老叟戏顽童”这个梗`。引用机器人消息后发送、私聊发送也支持。群内旁观消息不启动任务；需要明确梗名，指令不从旧对话猜测“这个”指什么。官方 QQ 和 NapCat 共用后端，官方仍须满足平台群消息授权。

每轮强制绕过本地搜索缓存和已有梗库，使用现有联网 Provider 检索梗义/出处和用法/场景，两次检索并行。只提交指定梗名，不提交群聊历史或成员身份。此入口仅学习搜索返回的网页正文/摘要，不打开视频或自动回退视频学习；原有指定 B 站链接学习入口保留。

审核分为两个独立模型调用：先从网页提取带逐字引文的候选结论，再审核主体匹配、证据支持、来源独立性、核心矛盾和置信度。程序再次验证引用原句确实存在、来源 ID 有效，去重相同 URL 和相同正文，同站子域不算跨站互证。只有模型审核为 high、确认来源独立，核心梗义有至少两个站点支持且存在经审核的用法，才写入共享梗库；这套规则不能保证网页本身正确，报告保留来源和疑点。中/低置信只报告候选结论，不进入共享记忆，不覆盖已有高置信知识。无法核实的出处不写入。

完整报告由现有日报渲染器生成 PNG，作为当前群/私聊的一条图片消息返回，包含梗义、已核实出处（若有）、用法/场景、置信度、审核理由、未确认项、来源链接及是否入库。先发送一条收到请求的提示，随后返回最终报告图片，不定时刷屏或附随机表情；沿用梗库有效期（默认 30 天），不是修改模型权重或永久记忆。报告模式为 `web-meme-learning-report`，不额外施加人工回复延迟。全局 `/指令` 输出已列出新命令，命令本身不要求超管。

学习过程和报告使用现有 `qq-video-learning.sqlite` 的 `video_learning_progress` 存储，键为 `web-meme-report:<UUID>`；记录含会话范围、检索材料、候选和审核结果、入库状态、时间戳。`web-meme-latest:<scope hash>` 保存会话最近一轮。报告在原请求内返回，官方使用被动回复窗口，不依赖主动群推送权限。服务重启会中断在途请求，不自动重发或重新学习；存档为 running/reviewed 的记录不能当完成结果。仅存档不等于 QQ 已送达。

使用现有群搜索/模型用量额度；全局最多并发两项，同一梗不并发重复学习，同一群完成一轮后冷却一分钟。模型提取和审核各最多 35 秒；搜索沿用既有 Provider 超时和失败处理。缺少配置、证据不足、审核超时或入库失败都会明确返回未完成/未入库结果。报告写盘失败单独注明。

验证：`node --test test/web-meme-learning.test.js test/web-search.test.js test/qq-service.test.js test/bridge-policy.test.js`；在真实 AstrBot 环境运行 `test/test_official_trial.py`，确认普通群成员命令进入后端且报告原群返回。测试不发送真实 QQ 消息。

进度与补取：群内 @ 后发送 `/learn-status` 或“学习进度”，立即返回当前会话最近一次任务阶段、耗时、材料数量和结果；查询绕过群串行处理队列，不调用模型。`/learn-report` 或“学习报告”补取已存完整报告，执行中则返回进度，不重新学习。同群成员可查询本群任务，不能查其他群或他人私聊。阶段变更实时写盘，进程重启后未完成任务显示中断；完成报告存档不表示 QQ 已送达，发送超时可用补取命令恢复。自然表达“你去学习一下114514相关梗的内容和关联，发个报告到群里”也进入显式学习链路。

报告投递修复：NapCat 曾连续两次发送同一份约 1200 字报告超时，无法据此确定具体原因。完整学习报告及 `/learn-report` 补取现在统一输出一张 PNG，保留正文和来源；`/learn-status`、用法和冷却提示仍为短文字。渲染失败只返回短失败提示，不退回同一长文本，也不自动重试 QQ 发送。图片生成成功不代表 QQ 已送达。

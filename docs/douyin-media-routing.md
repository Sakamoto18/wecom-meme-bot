# 抖音作品类型与缓存隔离

2026-10-07：修复偶发的「先分享图文，再分享视频」类型错误。

- 旧实现根据异步轮播计数器、全页播放器和资源请求推断类型；页面加载顺序会改变结果，误判后的成功结果还会缓存 10 分钟。未发现不同短链的缓存键碰撞。
- 新实现读取页面初始数据（RENDER_DATA / Pace）或详情响应，只接受与目标作品 ID 一致的类型及资源。当前实测图文类型为 68，普通视频为 0；未知类型、资源缺失返回失败，不猜视频、不写成功缓存。
- 图文仅使用该作品的 images，每张图的 video 仍走原有 MP4 → GIF 转换；静态图、动图按原位置输出。普通视频只用该作品的 video 播放地址。
- 每次请求独立保存详情响应；解析结果携带 sourceId / contentKind。短链跳转造成的页面上下文销毁可在时限内重试。

验证：普通图文 5 张静态图；动态图文 2 张图、2 段动效；普通视频 1 条。覆盖两种分享顺序、冷/热缓存、错误作品 ID、数据晚到、未知类型、图文混合动效位置及失败重试。

发布：配套发布 Provider 和 QQ 解析器，重建 QQ 容器清除进程内旧解析缓存；不删除登录态。回滚必须同时回滚两者并清除解析缓存。图文 GIF 转换参数和失败时回退静态图的行为保持原样。

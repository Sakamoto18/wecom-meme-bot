## 群内查询

NapCat 和官方 Bot 均支持 `@机器人 /远行商人`，普通群成员可用。每次重新获取本轮库存，发送一条正文 + 实时库存整理图，无需命中订阅道具，不 @ 订阅成员；午夜休息、来源过期或缺图会说明原因。支持显式 `/远行商人`，不做自然语言关键词路由。有两种 Bot 同时在群时，请 @ 希望回复的那个 Bot。

命令使用独立的 `command:<平台>:<群>:<消息ID>` 投递记录；重复事件、并发点击不会重复发图，也不会消耗定时提醒的本轮额度。

## 官方通道待启用条件

`official_trial_group_bindings` 必须有且仅有一个经过核验的 OpenID 指向 `913546080`；`merchant_official_member_bindings` 格式为 `{ "群OpenID": { "QQ号": "成员OpenID" } }`，群内提醒成员必须全部完成核验且不重复。此配置仅供商人提醒 @，不授予管理员权限。现有其他官方群不能作为替代目标。

官方发送先上传库存图，再使用官方消息接口一次发送图片、正文和对应成员的原生 OpenID @。收到消息 ID 才记为成功；平台返回不明确时保留待核验状态，不盲目重发。官方主动消息仍受平台权限/额度限制；部署时没有向未授权官方群发测试消息。群内命令使用触发消息 ID 被动回复，不依赖自动提醒的订阅成员映射。

## 私聊自动提醒

每人每轮使用 `private:<QQ号>:<轮次开始时间>` 独立记录。一次取源、筛选、制图，逐人发送正文与本轮完整库存图，不带群 @。收到各自消息 ID 才记为成功；某人发送失败不阻断其他人，已成功者不会重发。超时或无回执保留待核验状态，不盲目补发；明确拒绝按现有有界退避重试。

发送前检查好友列表，只调用不带 `group_id` 的 `send_private_msg`，绝不回退成群消息或临时群会话。未加好友者不消耗投递记录，加好友后本轮仍未过期即可接收。每人发送前再次检查轮次有效期。私聊回执不代表对方已读或手机必定响铃。

当前群与每个私聊收件人使用独立持久化投递键，已有本轮私聊记录不会阻止群补发，重启不会重复通知。未设置混合模式私聊名单时拒绝私聊，不能自动套用群 @ 名单。验证：`python -m unittest test.test_merchant_alert test.test_merchant_official test.test_merchant_private`。

每个目标的原始投递键追加 `:expiry30`，独立记录一次提醒；群和两人的回执互不影响。使用新采集与重新制图，文案标明已进入最后30分钟和实际剩余时间。重启后可在最后30分钟内补检，过期后不追发。若该目标直到最后30分钟才首次收到通知，则首次通知已起到到期提醒作用，不紧接着再发第二条。首次发送结果不明的目标先处理原回执，不盲发到期消息。

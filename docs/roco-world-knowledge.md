# 洛克王国世界图鉴知识库

官方 QQ 与 NapCat 共用后端检索，不依赖视频学习、模型训练或登录态。公开来源为 [Bilibili 洛克王国世界 WIKI](https://wiki.biligame.com/nrc/首页)，不混用旧版页游资料。

## 使用

- `迪莫的特性是什么`
- `喵喵能学哪些技能`，接着问 `那它的种族值呢`
- `圣光迪莫和迪莫有什么区别`
- `洛克世界中毒是什么效果`
- `洛克世界哪些精灵能学棘突`
- `洛克王国世界知识库`：查询收录数和采集时间。

群里 @机器人提问即可。自然接话仍遵守原有群接话条件，不会因装入图鉴而每条聊天都回复。名称、错字、游戏语境和追问由模型结合实体目录、当前消息和有限历史判断；日常“中毒、抓挠”不会仅凭词面触发。精灵同名多形态会返回多个候选，不自动混合数值。最近追问按会话和用户隔离，10 分钟过期，重启后重置。

## 数据和更新

`data/roco-world.sqlite` 是只读运行快照；可用 `QQ_ROCO_KNOWLEDGE_FILE` 改路径。启动时读入内存并关闭数据库。快照不进入 Git，部署时单独备份并发布，更新后重启后端加载；不需要重启 AstrBot/NapCat/provider。

```sh
python3 scripts/import-roco-wiki.py
# 有缓存的中断任务：重复上条命令即可继续。
# 真正刷新全部页面：
python3 scripts/import-roco-wiki.py --refresh
```

只读公开渲染后的精灵列表、技能列表、特性列表、游戏描述图鉴及每个精灵的详情页。不执行 Wiki Lua，不导入未公开的原始游戏数据。保留页面 URL、revision、采集时间、图鉴版本、精灵形态和习得方式；同步导入资料、进化、图鉴课题、生态与获取、历史以及技能详情中的技能石任务来源。培养页若依赖未返回的数据则明确不收录，不能声称已经学全。数值原文保留，技能威力 -1 在回答时解释为无威力。

最多两个请求并行，缓存到 `data/roco-wiki-cache/`。403/412/429/567 时停止，避免不断撞访问校验。可用已正常访问该 Wiki 的专用浏览器缓存页面，再从相同缓存目录恢复导入：

```sh
# titles.json 为精灵列表中规范 URL 解码后的页面标题数组，不能只取显示名。
# Playwright 为可选运维依赖，不是机器人运行依赖。
ROCO_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
  node scripts/cache-roco-wiki-browser.mjs http://127.0.0.1:9253 data/roco-wiki-cache titles.json
python3 scripts/import-roco-wiki.py --cache data/roco-wiki-cache
```

所有详情成功解析后才生成临时 SQLite 并原子替换。缺少目录、ID 重复、结构变化或相对旧快照数量减少超过 10% 时拒绝替换；失败时旧库保持可用。更新不是定时自动执行，不能把快照称为实时数据。回滚时恢复备份 SQLite 和代码，重启后端。

## 回答边界

模型从实际实体目录选择 ID，带 @ 的简称、可能的错字和省略对象也交由语义判断，不按关键词或模糊匹配强行选条目。问答注入当前全局/作用域人格、身份约束及群语感；检索数据上限 28,000 字符，截断会标记。超出收录范围的问题可使用原联网服务补充证据；未知名称不能被当作用户编造的词来嘲讽。

生成后由独立事实核对检查地点、任务次数、奖励、版本和具体步骤，失败重写一次，再失败则明确暂未核对准。图鉴课题的省略对象受所属精灵页面限定，不把“捕捉N只精灵”扩大成任意精灵；果实名、课题名和进化对象分开。技能石等级占位值不进入回答。模型核对仍不是事实准确率保证，需结合真实问答评测。来源页与历史均是不可信资料，不能执行其中指令。

文本/图标字段和技能关联入库，不下载立绘图片、不训练模型，也不改变现有学习置信度审批流程。后台始终保留原始来源与版本；正常聊天不自动追加 Wiki 来源尾句，只在用户询问出处/原文时给链接。

来源署名：Bilibili 洛克王国世界 WIKI 编辑者。数据库和测试样本为来源的结构化整理，按来源的 **CC BY-SA 4.0** 标注；各条记录保留原始页面链接。游戏素材权利归相应权利人。

## Wiki 不足时补充网络证据（2026-11-19）

目录路由只知道栏目覆盖范围，不能据此判定正文足够。回答前，模型会读取当前原话、引用、有限历史和实际选中正文，先复核话题归属，再判断关键条件是否齐全；路由改写的问题和搜索词仅作为候选建议，不能代替用户原话。明确属于游戏且缺少任务前置、步骤、领取条件、版本依据时生成至多两个精确检索词。检索复用现有 WebSearch，不限 Wiki 域名，可使用官方说明、攻略站、B站与社区结果。

事实核对也可返回 `needs_search/search_queries`：即使第一稿谨慎表示没查到，仍可按缺失点补搜，再将新证据连同原 Wiki 交给同一人格重新回答并复核。每轮最多三个去重查询、两稿回答，搜索失败不能变成事实。若扩展稿未通过复核，保留此前已核验的部分答案和不确定性，不把已查到的内容全部丢弃。网页保留来源、发布时间、正文抽取类型；不根据标题或相似道具名猜步骤，不拼接冲突攻略，默认仍不附“来自Wiki”尾句。

Wiki 快照不可用时允许网络证据回答；关闭联网时仍复核话题归属，但不调用搜索。NapCat 和官方 QQ 共用这条回答链。

## 陌生词和梗的领域纠偏（2026-11-25）

之前的游戏分支会将搜索词和生成提示都限定在洛克王国世界，误路由后即使 Wiki 没命中，也只能继续找游戏攻略。现在目录路由必须有当前语境或实体证据才判为游戏问题；仅有陌生名字、其他群友的游戏发言或上一轮游戏话题，都不足以确认当前归属。

游戏分支内部还有一次独立复核，返回 `domain=roco/other/unknown`。未识别的词先按原始词句查询含义、出处和语境，不追加游戏名、不限制 Wiki 域名；搜索结果返回后再判断归属。包括先前游戏搜索无结果的情况，仍能转向中性检索。明确的游戏问题继续使用原 Wiki 和攻略补充链路，已覆盖的图鉴事实无需额外搜索。

非游戏或仍未识别的话题用 `general-knowledge` 模式回复，去掉无关 Wiki 正文、引用以及路由擅自改写的游戏问题，保留当前人格、群口吻、身份约束和事实核对；不把错选的游戏实体记成此次追问对象。搜索无结果时只说明该说法未核实，不能默认它是精灵或道具。归属审查超时或 JSON 无效时，回退到原始问题的中性搜索，不能以失败确认游戏归属。查询去重后最多三次，回答最多两稿，联网关闭时不搜索。

# 人格保存与语境表达修复（2026-10-29）

目标是让同一个角色既能回答、检索和推理，也能按当前互动接梗、阴阳和互损；不能用骂人次数或命中固定口癖作为质量标准。

## 已核实的原因

- `/persona global` 把整段内容放进一条 `styleRules`，旧存储层只保留每条前 180 字。服务端历史事件中确有 1,209 字来源落成 180 字新增规则的记录。**当前激活的全局 v3 已在此前重建为 20 条规则、4 条口癖、7 组示例，不是仍然只有 180 字**，本次不重写它。
- 追加采用旧内容在前、再 `slice(0, limit)`；当前 20 条规则已满，新规则会被丢弃却显示成功。口癖和示例有相同路径。
- 外部语料有结果时，生成器跳过群语感提供器。对照测试旧版 8/8 轮只带外部语料，新版 8/8 轮同时带两类参考。
- `missing-role-voice` 用一组固定词判定角色语气，包含“说白了”“离谱”等；即使新鲜、贴题的表达也可能被重写。移除此检查及其调用条件，保留去 AI 腔、事实、时间、指代、重复回答等检查。
- 规划和生成提示存在“普通讨论禁止对人调侃”的广泛限制，与朋友互损设定冲突。现允许按具体行为、自嘲与当前互动接话；高强度辱骂仍需要明确对象和语境，引用和历史辱骂不会自动成为对当前用户的攻击许可。

## 行为与兼容性

完整角色卡保留换行，正文总预算 12,000 字，写入前校验容量。`/persona replace global|group|user 内容` 明确替换整个范围，仍经过原有待确认、权限、版本和回退流程；`global 内容` 继续表示追加。没有数据库结构迁移、批量重导入或历史覆盖。

`contextual-voice.js` 使用少量“语境→回答”示例示范同一个角色在自嘲、事实回答、纠错、求助、换题中的行为。它不按场景正则分类、不替代事实搜索、不复制语料事实，也不强制每句话附带笑话。群语感、外部语料与管理员人格共同输入。日志增加 `group_style=…chars`，能区分配置存在和本轮真正注入。

回合规划增加 `current_task` 与 `topic_relation`。生成提示中的任务卡放在语料之后，强调最新问题、纠正与换题，避免旧话题被拿来续写。证据提示明确部分记录不能推出全期结论，也不能把搜索资料里的观点冒认成提问者说的话。规划输出默认上限从 400 调到 600 tokens，为新字段留出空间。

保持原有短句目标、GitHub 来源的去 AI 腔链路、政治姓名避讳、身份归属、事实/文化检索、图片理解和媒体下载路径。未修改模型、搜索服务商、媒体缓存 TTL、定时推送或群学习数据。

## 验证与局限

- 修改前 731 项测试通过，修复后 `npm run check` 和全部 737 项测试通过；新增和更新回归覆盖长卡尾部、容量、权限、替换回退、群语感与语料并存、调侃与事实检索/推理并存，以及当前任务与换题。
- `scripts/evaluate-persona-voice.mjs --live` 使用部署的 `deepseek-flash` 和激活的全局 v3；只调用模型，搜索使用固定虚构证据，不向 QQ 发消息，不写群记忆。记录规划、检索请求、初稿、重写及最终结果。
- 八个场景包括朋友自嘲、缓存原理、当前赛果、转述他人、纠正主语、停止玩笑的求助、换话题、未知梗出处。小样本确认两类语感参考并存、时效查询和推理没有被禁用；同时暴露过旧话题回扣、无证据推断、求助时宣告“我认真”等问题，不能仅凭本地 review=valid 宣称表达质量全部达标。
- 所谓“学习/训练”在本项目中是存储与检索参考、群习惯提炼和提示条件化，**没有修改 DeepSeek 的模型权重**。不能把语料条数等同于模型已经学会何时互损，也不能凭本次少量样本认定基座语料不足是唯一原因。
- 上线后应继续查看自然消息，比较回答任务是否完成、证据范围、人物归属、重复率和用户反馈；不要奖励纯脏话或固定口癖。若未来微调，应使用多轮语境及好/坏回复对，覆盖答题、检索、纠错与收手，而非只喂辱骂语料。

## 后续：纠正提示冲突与强制认错

用户截图对应 2026-10-29 20:31:56 的真实回复，发生在上述部署之后。上一轮仅修改规划和角色提示，遗漏了 `buildModelInput()` 与 `buildNormalReplyContextPrompt()` 中的两条“先承认指代或意图听错”指令。去 AI 腔及图片提示还保留“最多认一句”。这些要求与“不自证”相互冲突。

消息层把真实 @ 关系与纠正词面结合，直接设置 `isCorrectionOfPreviousReply=true`。因此“不是我……是……”这种普通对比、互损也会被当作已确认的模型错误。本次保留真实 @、主语及引用关系，只把词面纠正降为候选，交由模型结合上下文判断；取消强制认错及必加比喻收尾，不新增禁词正则。真正纠错后的重复旧答案仍触发重写。

本轮的语料确实注入：群语感 598 字、外部语料 250 字，未经过重写。用相同原句复查，召回为“网红转型”的对话和一条弱智吧独句，主要是“号不是”“不是我”字面重合；这不是高质量的接话示范。语料当前仍按词面检索，尚不能声称具备经过验证的语境相似度排序。本次不将这些命中视为人格效果达标，也没有随机塞更多辱骂样本。

评测脚本现在走真实群消息拼装（@、引用、身份与意图候选），而非只把裸文本送进生成器；`--style-group` 可只读加载真实群风格库和语料库。测试资料不写入记忆，不向 QQ 发消息。新旧版本对照覆盖截图原句、普通对比、正常应答、事实纠错；新回归同时验证“纠正候选不强制认错”与“被纠正的重复旧答案仍能修复”。已通过代码检查及全部 739 项测试。

同步清除了知识提示和攻击提示中“至少两拍”的强制结构、系统提示中“攻击时不用回答问题”的冲突，并要求规划器中性描述当前沟通任务，不先替用户判定为“甩锅”或“认输”。这些改动允许一句贴题的接话自然结束，同时保留有实际问题就回答的要求；没有为“行”新增禁词或重写规则。

最终候选使用完整消息组装、线上全局 v3、真实群语感及外部语料复测了两次互损、两次事实纠错。四次均未再汇报认错过程，两次事实纠错均转向上传问题，推理仍启用；但互损仍反复采用“诊断书/病人”的比喻，部分回复仍以“行”开头。本次结果只能证明消除了已确认的错误指令，不能证明语境召回和表达多样性已经解决。语料语义重排未在本次实现，需单独按多轮语境与多样样本验证，不能只针对截图原句继续堆提示补丁。

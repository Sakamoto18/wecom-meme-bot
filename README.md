# 龙图机器人 - 支持QQ和企业微信

> QQ 版采用独立的 AstrBot + NapCat + OneBot v11 链路，不修改企业微信入口。部署步骤见 [QQ 部署文档](docs/QQ_DEPLOYMENT.md)。

用户在单聊或群聊中发送龙图请求或图片时，机器人只从 `memes/longtu/` 中经过校准的龙图库回复；目录尚未导出时才回退到 Mac 版企业微信本地 `Emotion` 缓存索引。通用表情包和普通熊猫头能力已关闭。项目使用企业微信官方 `@wecom/aibot-node-sdk`，SDK 自动处理长连接认证、心跳和断线重连。

## 架构与 Node.js 学习文档

如果你完全没有 Node.js 服务经验，先阅读[从零解释 Node.js 基础概念](docs/nodejs-foundations-explained.md)，再阅读[架构、设计与 Node.js 学习指南](docs/node-service-architecture-and-learning-guide.md)。两份文档分别负责解释概念本身，以及把概念放回消息主链路、会话并发、缓存、测试、部署和运行成本中。

## 1. 企业微信后台配置

进入智能机器人的配置页面：

1. 开启「API 模式」。
2. 接入方式选择「长连接」。
3. 复制长连接专用的 `BotID` 和 `Secret`。

切换到长连接后，原来的 Webhook 回调地址会停止生效。每个机器人同时只能保持一个有效长连接。

## 2. 填写凭证

编辑项目根目录的 `.env`：

```dotenv
WECOM_BOT_ID=你的BotID
WECOM_BOT_SECRET=你的长连接Secret
```

`.env` 已加入 `.gitignore`。不要把 Secret 提交到 Git 或发送到群聊。

## 3. 添加表情包

首次在 Mac 上完成龙图校准后运行：

```bash
npm run export:longtu
```

命中的龙图会按人工审查范围、排除哈希和内容哈希去重后复制到 `memes/longtu/`，可以随代码部署到服务器。

要直接读取 Mac 版企业微信的本地表情缓存，在 `.env` 中填写：

```dotenv
WECOM_EMOTION_DIR=/Users/你的用户名/Library/Containers/com.tencent.WeWorkMac/Data/Library/Application Support/WXWork/Data/账号ID/Emotion
```

项目会递归扫描该目录，只读取 PNG、JPG、JPEG 和 GIF 文件，不读取聊天文本。这个目录包含企微已经下载到本机的表情缓存，不保证等同于“收藏表情”列表；企微当前的缓存索引没有提供收藏标记。

服务器运行时直接读取仓库中的 `memes/longtu/`，不再依赖 Mac 的企微缓存绝对路径。

### 群成员标注

企微长连接消息只提供发送者 `userid`，项目默认将它哈希成稳定的 `群成员-xxxxxx` 标签。可以在 `data/member-aliases.json` 中按匿名标识人工填写昵称：

```json
{
  "a01da3": "玉涛龙大王",
  "20bf62": "爆豹"
}
```

已标注成员会以昵称进入大模型上下文；未标注成员仍使用匿名标签。可通过 `WECOM_MEMBER_ALIASES_FILE` 指定其他映射文件。

## 4. 启动

要求 Node.js 20 或更高版本：

```bash
npm install
npm test
npm start
```

看到 `企业微信长连接认证成功` 后，在企业微信中给机器人发送“表情包”或“梗图”。群聊里需要 `@机器人`。

普通对话启用大模型后，机器人会先完成流式文本回复，再通过同一条长连接主动推送一张本地 JPG/PNG 龙图。正常语聊会将用户原话和模型文案与图库文字做本地场景匹配；OCR 保存的是图片文字/场景标签，不会要求用户记住整句，也不会把整句当成手动口令。例如用户输入“玩原神玩的”，所有 OCR 文字含“原神”的龙图都会进入同一候选池，再按会话持久化洗牌轮换，而不是固定命中一张。只有明确说“发张龙图”时才保持全图库随机；未命中场景标签时也回退到全图库洗牌。管理员手动关键词池优先级最高。之所以拆成两条消息，是因为部分企微客户端不会渲染流式回复中的 `msg_item` 图片。附图准备或主动推送失败时，已经发送的模型文本不受影响。

龙图选择采用按会话持久化的洗牌袋：同一会话抽完整个可用池之前不重复，并在最近 12 次内尽量避开感知特征相近的场景。选择进度保存在 SQLite，进程重启后不会清空。

QQ 和企微的图库写入/删除只接受管理员的三个明确指令：`/add` 强制加入附图或引用图片，`/tag 关键词` 标记附图/引用图片（图片不在库时会先强制入库再标记），`/del` 引用删除或 `/del LT-XXXXXXXX` 按短 ID 删除。图片已在库时 `/add` 只会设为当前目标，不重复写入；刚刚 `/add` 的图片也可以在 15 分钟内直接 `/del`，误加图可立即回滚。自然语言“添加/强制添加/标记/删除”不再触发写操作，其他未列出的斜杠指令继续被拦截。关键词与图片是多对多关系：同一个关键词可以形成包含多张图的池，同一张图也可以加入多个关键词池；“发原神”等精确口令和普通对话中的“原神”都会从对应池按会话去重轮换。仓库内图片的文字标签来自 macOS Vision；Docker 运行时则使用本地 Tesseract 中文/英文 OCR，新图入库成功后自动识别表情包文字、写入场景标签并立即回查 SQLite。使用“标记列表”可查看数据库真实关键词池及每池图片数；引用图片发送“检查这张图”可查询是否入库及其全部手动标记；发送“检查标记原神”会显示该池的真实数量并轮换返回一张。每次标记成功前程序都会立即回查数据库，模型不能伪造成功提示。视觉复核、OCR、查重和图片定位都在本地完成，动态素材、软删除与关键词绑定保存在 `data/longtu-library/`。QQ 的权限、角色观察和身份钢印配置见 [QQ 部署文档](docs/QQ_DEPLOYMENT.md)。

QQ 群中明确 `@机器人` 时仍然必定进入普通回复；纯 `@机器人` 即使没有附加文字也会进入本项目的快速人格模式，强制关闭 thinking，并拦截“需要我帮忙、尽管说”等客服话术。允许群中的普通消息还会经过一层 ChatPlus 风格的三级“读空气”判定：点名、引用、明确提问/求助、风险或明显错误信息属于 `must`，直接接话；只是有趣且适合参与的话题属于 `may`，再检查群聊热度、无人接话退场、冷却、小时上限和概率；明确属于别人之间的对话则为 `no`。判定不回复时继续静默写入旁观记忆。主动回复的最终生成仍走本项目 Node 引擎，因此继续使用同一人格、长期记忆、联网检索和龙图库，不会调用 AstrBot 默认 LLM。普通回答会先保证事实和可执行性，再强制加入一句有明确靶子的高强度毒舌；“离谱、破玩意”之类软吐槽不能通过人格质检，真实痛苦、危机求助或明确要求停止对线时例外。深度思考只改变推理强度，不会冲掉这层人格。Bridge 会在处理任何 QQ 消息的第一步无条件停止 AstrBot 后续事件链，因此禁用群、关闭旁观、空消息、后端超时或报错等分支也绝不会掉进 AstrBot 默认模型。回复会引用原消息，原消息明确 `@` 第三人时优先 `@` 这些目标（最多 3 人），如果只 `@机器人` 则 `@` 发令者本人，并始终排除机器人自身和 `@全体成员`。主动回复不会介入明确 `@` 或引用其他群友的消息、图片消息、斜杠指令和机器人自身消息。成员本人发言后才会确认其昵称别名；别人 `@` 某人只登记稳定 QQ 身份，不会替对方确认昵称。成员画像会从本人发言中单独整理并永久保存在 SQLite，不受会话消息上限或 30 天会话 TTL 影响；询问“之前说过什么”时还会按稳定成员编号检索较早原文。已确认且在群内唯一的历史昵称可以在纯文字中锁定第三方目标，无需再次 `@`；重名或未确认昵称不会强行猜测。内部匿名编号只用于后台身份消歧，所有出站回复都会硬过滤，绝不发到群里。以 `/` 开头的消息只有 `/add`、`/tag`、`/del` 会被 Bridge 转发到图库服务；`/w`、`/help` 及其他插件指令无论旧配置项如何设置，都会在 Bridge 层直接停止，不回复、不写入本 Bot 的群聊记忆，也不会继续交给 AstrBot 的其他命令插件。

主动回复的产品思路参考 [ChatPlus / astrbot_plugin_group_chat_plus](https://github.com/Him666233/astrbot_plugin_group_chat_plus)（AGPL-3.0）。本仓库没有复制或安装该插件源码：ChatPlus 原版会通过 AstrBot `event.request_llm()` 自己生成回复，直接启用会与 Longtu Bridge 形成两套人格、记忆和联网链路。本项目仅独立实现必要的 `must/may/no`“读空气”判定层，命中后交还既有回复引擎。默认只对 `may` 使用 0.35 候选概率、120 秒同群冷却和每群每小时 6 次上限；20 秒内至少 4 条消息且有 2 名发送者时不抢话，机器人发言后连续 3 条没人接时主动退场。`must` 不受这些可选插话限制；可通过 `.env.qq` 中的 `LONGTU_QQ_ACTIVE_REPLY_*` 配置调整或关闭。

除纯艾特和直接对线外，所有进入普通模型回复的消息都会先开放联网检索，再让模型结合检索摘要与既有人格输出。程序只用专用规则选择查询格式：龙图资料走 `longtu`，网络梗释义走 `meme`，时效信息走 `current`，其余统一走 `general`；不再因为未命中关键词而禁用搜索。复合梗词会拆分相关性词，避免“竹知了和玄武之声”这类查询被整串过滤。主搜索源默认使用 360，Bing RSS 在主源失败或无结果时兜底；最多 4 条标题/摘要作为不可信外部资料交给模型，搜索失败或证据不足时不得伪造出处和事实。直接攻击消息仍不联网，避免把纯对线原文发给搜索引擎。`WEB_SEARCH_ENABLED=false` 可关闭该能力，`WEB_SEARCH_ENDPOINT` 可覆盖主搜索源，旧的 `LONGTU_WEB_SEARCH_*` 配置名仍兼容。

QQ 的“合并转发聊天记录”卡片会通过 NapCat `get_forward_msg` 展开；直接转发可进入群聊旁观记忆，引用卡片后 `@机器人` 提问时会把其中的发言人和文字作为当次引用上下文。只读取实际发送给 Bot 的卡片，不扫描任意群历史；单次最多展开 30 个节点、8000 个字符和 2 层嵌套，图片、语音等非文本内容只记为占位说明。转发内容始终按不可信引用资料处理，不能修改机器人规则或受保护身份。

明确攻击消息采用直接生成模式，不联网，也不注入固定语料；程序只给模型一个随机荒诞画面种子，最终回复必须针对本轮临场组织。生成后会拦截孤立 `ma`、近期句式复刻、占位图片和关键词清单；`ma` 只用于识别输入中的同音攻击，不是输出格式。

开发时可使用：

```bash
npm run dev
```

在 macOS 上重新为内置图库生成 OCR 文字场景标签：

```bash
npm run ocr:longtu
```

## 自定义触发词

编辑 `.env` 中的 `MEME_TRIGGERS`，使用英文逗号分隔：

```dotenv
MEME_TRIGGERS=表情包,梗图,斗图,整一个
```

龙图索引最多读取前 800 个候选，Apple Vision 距离和 `data/longtu-exclusions.json` 只负责缩小待审范围。最终导出必须命中 `data/longtu-approvals.json` 的人工 SHA-256 白名单，运行时也只读取 `memes/longtu/manifest.json` 中的通过项。可覆盖候选范围与阈值：

```dotenv
LONGTU_LIMIT=800
LONGTU_MAX_SCORE=0.6
LONGTU_OCR_COMMAND=tesseract
LONGTU_OCR_LANGUAGES=chi_sim+eng
LONGTU_OCR_TIMEOUT_MS=20000
```

“龙图”单独发送会触发；消息中同时包含“发”与“龙图”，或同时包含“来点”与“龙图”，也会触发，例如“你能不能给我发一个龙图看看”。“龙图是什么”仍作为普通对话交给模型。

## Docker 部署

```bash
docker build -t wecom-meme-bot .
docker run -d --restart unless-stopped \
  --name wecom-meme-bot \
  --env-file .env \
  -v "$(pwd)/memes:/app/memes:ro" \
  wecom-meme-bot
```

服务只需要访问外网的 `wss://openws.work.weixin.qq.com:443`，不需要公网 IP 或入站端口。不要同时运行本地和线上实例，否则新连接会踢掉旧连接。

## 工作方式

1. 收到 `message.text` 长连接回调。
2. 明确龙图指令直接选图；普通消息区分检索式攻击回复和大模型问答。
3. 文本回复后只从校准龙图库随机选择图片。
4. 通过 SDK 上传企业微信临时素材并用 `media_id` 发图。
5. 同一素材的 `media_id` 在进程内缓存 48 小时，避免重复上传。

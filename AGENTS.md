# Bot semantic routing

- User requirement: do not add keyword lists, substring matching, or regexes to decide natural-language intent, context retrieval, or historical-image relevance. Let the model judge the complete current request with bounded history, sender ownership, and candidate evidence.
- A historical message/image is a candidate, never a current attachment. Respect an empty model selection; invalid output or timeout must not force the latest image or the asker's image into the answer.
- Explicit quoted message IDs, protocol/URL parsing, permissions, resource limits, and documented command syntax may use deterministic rules. These are not semantic intent inference.
- Merged chat records are read only from an explicit quote in an addressed request. Never expand, prefetch images, or invent a reading request for directly posted or passively observed records. Within an authorized quoted record, expand nested records with shared depth/node/image limits and cycle detection; report unread content explicitly.
- In official QQ groups, reading merged records requires both an explicit quote and an @mention of this bot. A quote of the bot, an embedded URL, or a mention of another member cannot substitute for that mention. Recognize sender-owned record headers as well as the generic header, and reject unauthorized records before extracting links or calling the backend.
- Preserve official QQ and NapCat support. Create a branch before changes; validate and deploy authorized fixes before merging to main.
- User requirement: after committing and merging changes into `main`, proactively run `git push origin main` and verify the remote `main` commit matches local `main`. Do not stop at a local commit/merge or ask the user to remind you to push. Honor an explicit instruction not to commit/merge/push for a specific task. If pushing fails, report the reason and that remote synchronization is incomplete; do not force-push over remote changes. See [development workflow](docs/node-service-architecture-and-learning-guide.md#104-提交合并与远端同步).
